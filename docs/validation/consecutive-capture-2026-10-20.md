# 2026-10-20 连续观测配对修正

已按用户确认的方案复用相邻实测观测，消除逐帧等待一个周期后再查询目标的额外开销。
状态 13D、世界系绝对动作 9D、任务标签及 AV1 流式编码配置保持原有定义。

## 实现与边界

`record-real` 在原生每段 `record_loop` 外包一层配对上下文：

1. 循环前预采首个观测，等待一次目标采样间隔。
2. 每周期只查询一次状态并保存双相机快照；返回上一观测，以本次实测 TCP 作为后继动作。
3. 原生循环负责后续节拍与写入；下一样本的 source 复用上一样本的 target。
4. 每段循环退出即清空缓存，覆盖保存、重置、重录、恢复与异常，不跨边界携带观测。

首帧和末帧都有真实后继状态，不使用零动作或复制末帧动作。
图像取帧后复制，防止设备复用缓冲区时覆盖上一观测。
没有复制原生录制循环，也没有修改安装的 LeRobot 或 CPS SDK。
连接日志标记 `sampling_mode=consecutive_observations`。

## 回归证据

确定性回归测试使用真实 `record_with_conditions` 和原生 `record_loop`，
模拟每次 SDK 查询耗时 3 ms、四个采样周期：

| 指标 | 修改前 | 修改后 |
|---|---|---|
| SDK 查询次数（含连接标定） | 9 | 6（标定 1、首观测 1、后继 4） |
| 循环频率 | 约 27.5 Hz | 30 Hz |
| 慢周期告警 | 4 条 | 0 条 |
| 相邻样本 source/target | 独立重复查询 | 复用相同实测状态及主机时间 |

已有 Pixi dev 环境中，采集、标签、schema、相机、设备及脚本入口测试 **57 项通过**。
覆盖原生保存、重录、重置、恢复、图像快照、异常清理、动作统计和训练数据检查。
这证明额外等待问题在可控场景已解决，不代表物理设备实时性已经验收通过。
