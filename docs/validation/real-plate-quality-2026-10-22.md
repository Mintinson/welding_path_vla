## 需要处理的问题

### 1. 采集日志与正式数据目录分离

检查时的 `configs/real_record.yaml` 中：

```yaml
robot:
  capture_root: datasets/real/elfin_demo
dataset:
  root: datasets/real/elfin_welding_path_plate
```

正式数据目录缺少 `meta/real_capture_contract.json` 与 `meta/real_sessions/`。
在 `elfin_demo/meta/real_sessions/3e7123e435f248298fe36cda52fa4bf2.jsonl` 中找到了对应会话。
十条完整采集链的每一帧 state/action 转换为存储的 float32 后，均与本数据集逐元素精确一致；
匹配的链编号为 0、2、4、6、8、10、12、14、16、20。
日志还包含重置或未保存的链，因此不能把整份日志按行直接当作正式样本。

影响：单独迁移正式目录会丢失真实时序、有效 TCP 标定和来源证明；
`prepare_real_dataset()` 会因缺少采集契约而失败。适配器目前只检查 capture_root 中的
robot_type/FPS，没有检查它与原生 dataset.root 是同一目录；已有旧目录符合这两项时，
这个配置错误能够通过连接阶段。

建议：后续让两处路径一致；这一批只恢复已精确匹配的会话与一致的采集契约，
保留旧位置文件，不混入其他会话。此次只在验收副本完成恢复，没有修改正式目录。

### 2. 当前统计仍为 absolute action，缺少训练 manifest

正式目录没有 `meta/welding_path_vla_export.json`。实际调用项目 `validate_dataset()` 返回：

```text
ValueError: 数据集缺少 relative_action manifest, 请重新导出
```

这里不是要求重新采集或重新编码。应执行真机整理入口，按训练要求计算 relative-action
统计并生成 manifest，不能手写一个 manifest 跳过检查。

当前 `meta/stats.json` 的 action 位置均值约为 `[0.427162, -0.037292, 0.333578]` 米，
对应世界系绝对目标。使用项目共享函数、horizon=30 / stride=1 重算得到的相对位置均值约为
`[0.000898, 0.002306, -0.001194]` 米。若绕过检查并使用旧统计，
会使 relative-action 目标与归一化尺度不匹配。

独立验收副本 `outputs/validation/plate_quality_20261022/prepared_copy/` 中，
只复制 metadata，视频和数据文件通过符号链接引用原件，避免重复占用磁盘。
执行 `prepare_real_dataset(..., reference_dataset="datasets/weldpath_lerobot_relative_small")`
成功，随后项目 Trajectory-VLA 的数据契约检查通过：state=13、action=9、
relative_action、horizon=30、stride=1。原始数值和 metadata 的 SHA-256 及文件列表均未改变。
副本只是验证产物，后续正式训练仍应使用整理后的正式目录。

### 3. 摄像头帧的新鲜度和同步仍有可观测性缺口

完整视频解码后，对相邻 RGB 数组做逐像素相等检查，排除 episode 边界：

| 指标 | global | wrist |
|---|---:|---:|
| 完全相同的相邻画面对数 / 8,011 对 | 810 | 764 |
| 比例 | 10.11% | 9.54% |
| 机器人单步位移 >0.1 mm 时相同的画面对数 / 6,230 对 | 75 | 91 |
| 运动期比例 | 1.20% | 1.46% |
| 重复画面期间最大机器人单步位移 | 1.367 mm | 1.392 mm |
| 最长连续相同画面 | 2 帧 | 2 帧 |

重复主要集中在静止时，没有发现长时间冻结。静止图像经过有损编码也可能完全相同，
所以不能把全部相同画面解释为相机丢帧，也不能只用视频帧数齐全证明每次采样都有新曝光。
运动期的少量重复需要关注，可能影响图像与机器人状态的精确对齐。

适配器当前使用非阻塞 `read_latest()`，没有新图像时可以复用上一张图；
日志的 `camera_read_s` 只标记主线程取图完成时间，没有记录取出的图像对应的后台接收时间、
帧序号或曝光时间。仅凭本批已保存文件，无法确定重复发生在摄像头、取帧还是编码阶段，
也无法量化真实视觉延迟。建议后续记录图像帧序号和对应接收时间，再据此监控帧龄、
复用率和双相机偏差；不要简单把读取改成阻塞等待两台相机，否则可能再次拖慢采样循环。

### 4. 首尾等待和示范覆盖范围

按相邻 TCP 位移超过 0.02 mm 确定首次/末次明显运动，首尾等待合计约 53.97 秒，
占名义时长约 20.2%。按单步位移小于 0.01 mm 统计，近静止区间约占全部间隔的 20.2%。
这些阈值是诊断定义，不是自动 phase 标签或删帧标准。

首尾保留少量静止有利于观察初态和终态，但连续数秒停留会增加零动作监督，
模型可能学到延迟启动或过早停下。建议缩短录制前后无关等待；已有数据如需裁剪，
应使用完整的 episode 编辑流程并重算 metadata、时序边界和 relative 统计，
不能只删除 Parquet 行。

接触表可见约五组工件摆放，每组两次示范；10 个 episode 只有约 4.5 分钟。
适合初步训练和过拟合验收，不能据此证明不同工件位置、光照或反向运动下的泛化。
划分验证集时应整组留出工件摆放，避免同一摆放的近重复轨迹同时进入训练和验证。
全部 forward 与当前采集要求一致，但这批数据没有覆盖 reverse；
标签正确性仍依赖人为定义并遵守工件的起止端，不能由世界系某一坐标增减自动判定。

## 通过的检查

- 10 个 episode 的长度总和、Parquet 行数、info.total_frames 均为 8,021；
  全局 index、回合内 frame_index、dataset_from/to_index 连续且一致。
- 每回合 timestamp 与 frame_index/30 一致，最大误差不超过 float32 精度。
- 所有状态和动作有限；wxyz 四元数范数误差不超过约 6e-8，
  action 的两行旋转向量单位长度误差不超过约 2.4e-7、正交误差不超过约 8.5e-8。
- 除各回合最后一个目标由日志验证外，所有 action[t] 的位置与 state[t+1] 精确一致，
  旋转 6D 与后继四元数转换结果最大差约 3e-8。全部 8,021 条含末帧的配对也通过日志精确匹配。
- 两路视频逐帧完整解码，各为 8,021 帧，PTS 严格以 1/30 秒递增，无解码错误；
  AV1 的实际解码器名称为 libdav1d。保存的 video.info 与参考集逐项一致。
- 两路图像都有正常内容和变化，抽查 global/wrist 视角分配合理，没有全黑视频。
  腕部视角在接近和退出期间会看不到完整工件；全局视角可以补充，但工件在全局图像中较小，
  工具尖端是否始终精确位于焊缝中心不能由接触表或编码指标给出保证。
- 实际项目数据构造器配合 PyAV，成功读取每回合首、中、尾共 30 个样本；
  action chunk 为 `[30, 9]`，末帧 padding=29，没有跨回合拼接。
  训练默认使用的 TorchCodec 后端另抽查 8 个首尾/回合边界样本，均成功读取。
- 用最低 TCP 高度上方 3 mm 内的连续区间作几何诊断，各回合近工件段 XY 长度约
  112.5–118.1 mm，拟合自身直线的横向残差 P95 约 0.054–0.121 mm。
  这只是轨迹自身直线度，不是相对真实焊缝的跟踪误差；没有焊缝真值、相机外参或空间基准测量，
  不能据此认证毫米级沿缝精度。
