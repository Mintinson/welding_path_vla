# ADR 0008：真机被动采集直接保存 LeRobot 数据

状态：已接受并实现（2026-10-18）；待实机验收。对真机被动采集部分替代 ADR 0002。

真机被动采集使用原生 `lerobot-record` 保存完整路径示范，并复用其相机、键盘、回合和数据写入能力；不再要求先保存仿真 raw episode。采集结束后增加轻量整理步骤，校验动作时序、补齐项目动作契约与 relative action 统计，使数据进入现有训练链路。

该选择减少了重复维护录制流程和格式转换的成本。代价是这类真机数据以 LeRobot 为存储依据，无法直接使用依赖仿真 raw 内容的重渲染或参考轨迹诊断；工具标定、坐标定义、可获取的采集时序和实测动作来源需另行记录。仿真数据仍遵循 ADR 0002；真机动作语义遵循 ADR 0007。

2026-10-19 补充：`record-real` 使用薄配置入口调用原生 `lerobot_record.record()`。
由于本机 0.6.0 录制配置没有通用附加字段入口，包装仅在当前调用期间适配 schema 与每帧数据组装，
保存用户指定的 `task.direction`、可选 `task.parameters` 和自定义 `task.extra.*` 标量。
不推断方向、不验证动作是否符合标签，也不复制原生回合、键盘、恢复和写入逻辑。

2026-10-20 补充：相邻实测观测连续配对。薄封装在每段原生 `record_loop` 前预采首个观测，
等待一次首对间隔；之后每周期只查询一次状态，返回上一观测并以本次状态作为后继目标。
每段循环退出时清空缓存，覆盖录制、重置、重录和异常退出，避免跨回合使用旧观测。
首尾样本均有真实后继状态，不补零、不改变 13D 状态和 9D 绝对动作定义。

2026-10-22 补充：`dataset.root` 是唯一的数据位置配置，移除重复的
`robot.capture_root`。薄封装在连接适配器前绑定当前原生数据目录，使额外采集契约和会话日志
与视频、Parquet 一起保存；省略 root 时沿用原生已加时间戳的 repo_id 默认路径。
